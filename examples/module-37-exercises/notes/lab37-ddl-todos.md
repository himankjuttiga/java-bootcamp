### Why index the foreign key column

PostgreSQL creates an index for a primary key and for every unique constraint automatically. It
does **not** create one for the referencing column. Two consequences:

1. `SELECT ... FROM account JOIN customer ON ...` scans the whole `account` table for each lookup
   of a customer's accounts.
2. Every `DELETE` or key `UPDATE` on the parent forces a sequential scan of the child table to
   check the constraint. On a large `account` table this turns a single-row delete into minutes.
